# 동양생명 프로젝트 ML 구현 발표자료

작성 기준: 2026-09-29  
대상 브랜치: `namuking1/customer-ml-fallback-main`

> 발표 핵심: 고객 더미데이터를 검증·전처리하고, 상품과 특약을 두 단계로 분류하는 모델을 구현했습니다. 새로운 고객 조건에도 두 개의 비교 후보를 제시하며, 검증 데이터에서 정답 상품의 Top-2 포함률은 81.5%였습니다.

---

## 1. 프로젝트와 담당 역할

이 프로젝트는 보험설계사의 상담 업무를 지원하는 Streamlit 기반 AI 세일즈 도구입니다.

제가 담당한 ML·데이터 영역은 다음과 같습니다.

- 고객 CSV 및 정렬 ZIP 검증·전처리
- 가입상품과 가입특약 예측 모델 구현
- 중복과 데이터 누수를 막는 평가 구조 설계
- 새로운 고객 조건을 처리하는 확률 기반 예측
- 모델 저장·재사용을 위한 Joblib 캐시
- 고객 분류·정렬 분석 보고서 생성
- 별도 목업 보장·예산 적합성 실험
- 기존 챗봇 및 Streamlit 화면과 ML 모델 연결

---

## 2. 문제 정의를 바꾼 이유

초기에는 월 보험료를 예측하는 회귀 모델을 구현했습니다. 하지만 제공된 고객 CSV에는 실제 월 보험료 정답이 없고, 가입상품과 가입특약만 포함돼 있었습니다.

따라서 현재 기본 모델의 문제를 다음과 같이 정의했습니다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 고객 조건 9개 |
| 1단계 정답 | 가입상품 4종 |
| 2단계 정답 | 선택 상품에 속한 가입특약 |
| 사용하지 않는 정답 | 월 보험료·가입 가능 여부·고객 적합성 |

공개 보험료 72건으로 만든 과거 회귀 모델은 별도 참고 모델로 남겼습니다. 데이터에 없는 보험료를 고객 추천 모델이 예측한다고 설명하지 않는 것이 핵심 판단이었습니다.

---

## 3. 학습 데이터

`customer_data.csv`의 생성 더미데이터 5,000건을 사용합니다.

### 입력 변수 9개

- 숫자형 4개: 나이, 연소득, 직업위험등급, 자녀 수
- 범주형 5개: 성별, 결혼 여부, 흡연 여부, 만성질환, 가족력

### 예측 대상

- 가입상품: 암·건강보험, 간편심사보험, 종신보험, 연금보험
- 가입특약: 각 상품에서 선택할 수 있는 특약 또는 선택 안함·특약 없음

`분석ID`, `상품분류`, `특약상태`처럼 정답을 직접 또는 간접적으로 알려주는 열은 입력에서 제외했습니다.

---

## 4. 모델 구조

```text
고객 CSV 또는 정렬 ZIP
        ↓
필수 열·결측·범위·범주·상품/특약 조합 검사
        ↓
숫자형 4개 유지 + 범주형 5개 원핫 인코딩
        ↓
1단계 RandomForest: 가입상품 분류
        ↓
2단계 상품별 RandomForest: 해당 상품의 특약 분류
        ↓
상품 1·2순위와 상품별 특약 후보 제공
```

특약을 전체 상품에서 한 번에 분류하지 않고 상품별 모델로 나눴습니다. 따라서 선택한 상품에 존재하지 않는 특약이 섞이는 문제를 방지합니다.

## 5. 데이터 검증과 누수 방지

모델 점수보다 먼저 평가가 공정한지 확인했습니다.

1. 정렬 기준만 다른 CSV 6개가 동일한 고객 1,000건인지 비교합니다.
2. 같은 자료를 여섯 번 합쳐 중복 학습하지 않습니다.
3. 동일한 9개 입력 조건을 하나의 그룹으로 묶습니다.
4. 같은 조건 그룹이 학습과 검증에 동시에 들어가지 않게 분리합니다.
5. 최종 검증 자료는 모델 설정 선택에 사용하지 않습니다.
6. 최빈 상품만 고르는 기준선과 비교합니다.

5,000건 데이터의 최종 분할은 다음과 같습니다.

| 항목 | 값 |
| --- | ---: |
| 학습 고객 | 3,986건 |
| 검증 고객 | 1,014건 |
| 학습 조건 그룹 | 3,493개 |
| 검증 조건 그룹 | 874개 |
| 양쪽에 겹친 조건 그룹 | 0개 |

## 6. 모델 고도화 과정

| 초기 버전 | 고도화 버전 |
| --- | --- |
| 1,000건 더미데이터 | 5,000건으로 확장 |
| 조건 완전 일치 시에만 결과 표시 | 유효한 새 조건도 `predict_proba()`로 추정 |
| 고정 RandomForest 설정 | 학습 데이터 내부 그룹 검증으로 후보 비교 |
| 실행 시 반복 학습 가능 | Joblib 모델 저장 및 데이터 해시 캐시 |
| 1순위 정확도 중심 | Top-2, macro F1, 상품·특약 동시 성능 추가 |
| 모델만 별도 실행 | 기존 챗봇 호출 함수에 연결 |

선택된 RandomForest 설정은 트리 160개, 최대 깊이 6, 리프 최소 표본 4개, 난수 시드 42입니다.

## 7. 검증 결과

| 평가 항목 | 결과 |
| --- | ---: |
| 상품 1순위 정확도 | 57.7% |
| 상품 Top-2 포함률 | **81.5%** |
| 상품 macro F1 | 0.5542 |
| 상품·특약 동시 정확도 | 46.1% |
| 상품·특약 Top-2 포함률 | 65.5% |
| 정답 상품을 알려준 경우 특약 정확도 | 80.8% |
| 최빈 상품 기준선 | 33.9% |
| 새로운 유효 조건 결과 표시율 | 100% |

### 발표에서 사용할 핵심 표현

> 1순위 상품 정확도는 57.7%로 최빈 상품 기준선보다 약 23.8%p 높았습니다. 상품 하나를 단정하는 대신 두 개의 비교 후보를 제시했을 때 정답 상품 포함률은 81.5%였습니다.

`정확도 81.5%`라고만 말하지 않고 반드시 `상품 Top-2 정답 포함률 81.5%`라고 표현합니다.

---

## 8. 1순위 정확도가 57.7%인 이유

더미데이터 생성기는 가장 높은 점수의 상품을 정답으로 고정하지 않습니다. 조건별 상품 점수를 확률로 바꾼 뒤 `np.random.choice()`로 정답을 추첨합니다.

따라서 같은 조건의 고객도 서로 다른 상품 라벨을 가질 수 있습니다.

생성 규칙을 직접 적용해도 다음 수준입니다.

| 생성 규칙 자체의 결과 | 값 |
| --- | ---: |
| 1순위 평균 선택 확률 | 약 55.2% |
| 생성된 라벨과 규칙 1순위 일치율 | 약 56.1% |
| 생성된 라벨의 규칙 Top-2 포함률 | 약 80.6% |

현재 모델의 상품 정확도 57.7%는 이 확률적 생성 구조에서 사실상 1순위 상한에 가까운 결과입니다. 1순위 80%가 필요하다면 라벨을 확률 추첨이 아닌 결정 규칙으로 만들거나, 실제 고객 선택을 설명할 추가 변수를 확보해야 합니다.

## 9. 별도 목업 적합성 실험

가입 이력 예측과 별도로 보장 목표·예산을 포함한 목업 실험도 구현했습니다.

추가 입력은 다음과 같습니다.

- 우선 보장 목표
- 추가 보장 목표
- 월 예산 구간

RandomForest와 HistGradientBoosting을 비교해 Boosting을 선택했습니다. 보장 및 목업 예산 규칙을 만족하지 않으면 `예산·보장 재검토`를 반환합니다.

| 항목 | 결과 |
| --- | ---: |
| 목업 정책 재현 정확도 | 99.9% |
| 추천 제공률 | 54.5% |
| 예산 규칙 위반 | 0건 |

이 99.9%는 사람이 만든 목업 정책을 재현한 정확도입니다. 실제 고객 추천 정확도나 보험 가입 적합성으로 소개하지 않습니다.

## 10. 앱 연결과 실행 성능

`ml_model.get_recommendation()`의 기존 반환 형식을 유지하면서 새 모델을 연결했습니다.

- 기존 챗봇 코드가 같은 호출 방식을 계속 사용
- 유효하지 않은 입력은 `자료가 없음` 반환
- 새 고객 조건은 확률 기반 후보 제공
- 기본 학습 모델을 `artifacts/customer_ml/model.joblib`에 저장
- 데이터 해시와 scikit-learn 버전이 같으면 즉시 재사용
- CSV가 변경되면 모델을 다시 학습

이를 통해 모델 변경이 기존 앱 전체를 깨뜨리지 않도록 호환성을 유지했습니다.

## 12. 1분 발표 원고

안녕하세요. 저는 이번 프로젝트에서 고객 데이터 전처리와 상품·특약 추천 모델을 담당했습니다.

고객 CSV에는 실제 보험료가 없기 때문에 문제를 보험료 예측이 아닌 가입상품과 가입특약 분류로 정의했습니다. 나이, 성별, 연소득, 직업위험등급, 결혼 여부, 자녀 수, 흡연 여부, 만성질환, 가족력의 9개 조건을 사용합니다.

첫 단계 RandomForest가 네 가지 상품 중 후보를 분류하고, 두 번째 단계에서는 상품별 모델이 해당 상품의 특약을 예측합니다. 같은 고객 조건이 학습과 검증에 동시에 포함되지 않도록 그룹 단위로 분리해 데이터 누수를 방지했습니다.

5,000건의 더미데이터를 평가한 결과 상품 1순위 정확도는 57.7%로 최빈 상품 기준선보다 약 23.8%p 높았습니다. 상품 하나를 단정하지 않고 두 개의 비교 후보를 제시했을 때 정답 상품 포함률은 81.5%였습니다.

또한 처음 보는 유효한 고객 조건도 예측하도록 확률 기반 fallback을 추가했고, 학습 모델을 Joblib로 저장해 반복 실행 속도를 개선했습니다. 다만 결과는 생성 데이터의 가입 패턴을 학습한 것이며 실제 보험 적합성이나 가입 확률을 의미하지 않습니다.

## 13. 예상 질문과 답변

### Q. 정확도가 57.7%면 낮은 것 아닌가요?

라벨이 최고 점수 상품으로 고정되지 않고 확률적으로 추첨됩니다. 생성 규칙 자체의 1순위 기대 확률이 약 55.2%이므로 현재 결과는 생성 구조의 상한에 가깝습니다. 실제 서비스에서는 하나를 단정하기보다 Top-2 비교 후보를 제공하며 이때 포함률은 81.5%입니다.

### Q. 특약 정확도 80.8%가 전체 추천 정확도인가요?

아닙니다. 정답 상품을 이미 알고 있을 때 특약 단계만 평가한 조건부 수치입니다. 상품부터 특약까지 모두 맞힌 동시 정확도는 46.1%입니다.

### Q. 목업 모델의 99.9%는 실제 고객 정확도인가요?

아닙니다. 사람이 정의한 보장·예산 목업 규칙을 모델이 재현한 수치입니다. 실제 보험료나 가입 가능성, 고객 적합성을 증명하지 않습니다.

### Q. 왜 상품과 특약 모델을 나눴나요?

특약은 특정 상품에 종속되기 때문입니다. 전체 특약을 한 번에 분류하면 선택한 상품에 없는 특약이 나올 수 있어 상품별 특약 모델로 분리했습니다.

### Q. 담당 성과를 한 문장으로 말하면?

> 고객 더미데이터를 검증·전처리하고, 상품과 특약을 두 단계로 분류하는 모델과 누수를 방지한 평가 구조를 구현했으며, 새로운 고객 조건을 처리하는 fallback과 모델 캐시를 기존 앱에 연결했습니다.
